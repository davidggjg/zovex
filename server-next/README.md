# zovex-server-next — נתיב `/stream` ב-Go

מימוש של `/stream` מעל [`gotd/td`](https://github.com/gotd/td), במקום Pyrogram.
**לא מחליף את השרת החי** — הבוט, הפאנל, `content.json`, ה-HLS relay, ה-EPG
וההעלאות נשארים בפייתון. רק משיכת הווידאו מטלגרם עוברת לכאן.

## למה

Pyrogram הועברה לארכיון בדצמבר 2024, וגרסתה האחרונה היא מאפריל 2023. הקוד
שלנו נשען על פנימיים שלה (`session.Session`, `Auth`, `raw`) שאף אחד לא
מתחזק. `gotd/td` פעילה, מסומנת `stable`, נבדקת מקצה-לקצה מול שרת טלגרם
אמיתי ב-CI, ומריצה בוט קנרי בייצור שבודק דווקא **דליפות זיכרון והתחברות
מחדש** — בדיוק סוג התקלה שסבלנו ממנה.

מדידה על השרת עצמו: פייתון החזיקה 5 צופים במקביל, הגרסה הזאת 15 ומעלה.

## תאימות לאחור

החתימה זהה ביט-לביט ל-`_stream_sig` שב-`main.py`:

```
HMAC-SHA256(SIGN_SECRET, "{chat}/{msg}/{exp}").hexdigest()[:32]
```

לכן **8,682 הקישורים החתומים שכבר בקטלוג עובדים כמו שהם**, בלי המרה ובלי
לגעת ב-`content.json`. יש על זה בדיקה (`TestStreamSigMatchesPython`) עם
וקטורים שחושבו בנפרד ב-`hmac`/`hashlib` של פייתון.

## משתני סביבה

| משתנה | חובה | הערה |
|---|---|---|
| `API_ID`, `API_HASH` | ✔ | כמו בצד הפייתוני |
| `BOT_TOKENS` | ✔ | מופרד בפסיקים |
| `STREAM_CHANNEL_ID` | ✔ | מזהה הערוץ, בלי הקידומת `-100` |
| `STREAM_CHANNEL_ACCESS_HASHES` | ✔ | **אחד לכל בוט, באותו סדר** — ר' למטה |
| `STREAM_SIGN_SECRET` | ✔ | חייב להיות זהה ל-`SIGN_SECRET` שב-`/opt/zovex-bot/.env` |
| `LISTEN_ADDR` | | ברירת מחדל `:8080` |
| `STREAM_PREFETCH` | | כמה קטעים באוויר. ברירת מחדל 4 (= עד 4MB לצופה) |
| `STREAM_CHUNK_RETRIES` | | ניסיונות חוזרים לקטע. ברירת מחדל 3 |

### `access_hash` הוא לכל בוט בנפרד

ממצא שנמדד ב-06/09: `access_hash` ספציפי לחשבון שביקש אותו. בוט שמנסה
להשתמש ב-hash שקיבל בוט אחר מקבל `CHANNEL_INVALID`. לכן כל בוט מחזיק את
ה-`InputChannel` שלו, ואותו בוט שפתר את ההודעה מושך גם את כל הבייטים שלה
— לא מתחלפים באמצע. **זה נכון גם בצד הפייתוני.**

## הרצה

```bash
go build -o zovex-server-next .
go test -race ./...
```

## מה עובד

- אימות חתימה, `Range`, `HEAD`, `206`, `Content-Range`
- משיכה מקדימה מקבילה עם מסירה **לפי הסדר** — בזמן שקטע נכתב לצופה,
  הבאים כבר בדרך. זה התיקון נגד תקיעות באמצע, ובדיוק מה ש-TG-FileStreamBot
  הוסיפו ב-v3.2.0 כשעברו ל-Go
- ניסיונות חוזרים עם השהיה עולה, כיבוד `FLOOD_WAIT`, ופתירה מחדש
  אוטומטית ב-`FILE_REFERENCE_EXPIRED`
- ה-`ctx` של הבקשה מגיע עד ללולאת המשיכה: צופה שעוזב או קופץ עוצר את
  המשיכה מיד, במקום שתמשיך לרוץ לחינם
- כיבוי מסודר ב-SIGTERM, ו-`/healthz` שמחזיר 503 עד שהבוטים מחוברים

## מה עוד לא

- **הפניית CDN** (`upload.fileCdnRedirect`) — דורשת AES-CTR ו-reupload
  token. הבדיקות מול הערוץ שלנו לא נתקלו בזה; מוחזרת שגיאה מובחנת
  (`errCDNRedirect`) כדי שנזהה בלוג אם זה כן קורה בייצור
- לא נבדק לאורך ימים תחת עומס אמיתי. זו הבדיקה היחידה שתוכיח שהתקיעות
  המצטברות נעלמו, כי גם השרת הפייתוני נקי לגמרי בשעות הראשונות
